# Drawing one direction

You are a helper: you draw one direction of a design, and the lead draws nothing of it. Your prompt gave you its name and slug, its line and idea, the facts, the person's answers, what must hold in every direction, the skill's folder and the folder you build in. Below, Night Watch stands for your direction's name, `night-watch` for its slug, `<skill>` for the skill's folder and `<folder>` for the folder you build in. The design shows each fact and requirement; the page never quotes one.

1. **Your first part, at once:** the direction's top as the product's user will see it (the product's name, then the headline and line from your prompt, word for word), with its styles inside that same part. When your prompt names `draw/DESIGN.md`, Read it and `draw/CHROME.html` first, in one message: use only its values and parts, and your first part is the chrome as it is, with this screen in its content area (references/product.md).
2. **Each part** is one Write call to `<folder>/draw/night-watch/01.html`, `02.html` and on, and each change to a part one Edit call (never a heredoc or `sed`). Its first line is `<!-- status: Night Watch: <the part> -->`, every id in it starts `night-watch-`, and it takes at most 45 seconds of writing. One more part may go out before the brief if it needs no real label or row; a list, a table, a nav or anything named waits for it.
3. **Read the brief once,** `node <skill>/assets/fold.js -C <folder> brief` (it waits for it), think the rest through once, and send it as parts in one message, no checks between them.
4. **Your last part is the script** for Night Watch's own tabs, filters and buttons. It gives each `control:` in the brief (a state on the Prototype bar) its value on your section and a rule for every value but the one it opens on, so each value really changes what shows. Put `<span class="k-sample">Sample</span>` beside each thing a `sample:` line names. Anything it builds (cards, rows, lists, counts) it builds in one function run with `ssDraw(fn)`, which draws it now and after every push. Its code goes inside `(() => { … })();`, with no `const`, `let` or `class` outside it: a push that changes a script runs the page's scripts again in the same tab, and a name declared at a script's top a second time stops that whole script.
5. **Then your about part,** `<folder>/draw/night-watch-about/01.html`, one Write call, once the direction can be tried: it goes in the block above your direction on the canvas, for the person choosing, never inside the design. In your own words, quoting nobody (references/directions.md, "About blocks", says what each holds):
   ```html
   <!-- status: Night Watch: what it is -->
   <p class="about-intro" data-ss-id="night-watch-about-intro">2 or 3 sentences: what it is for and gives up, then how to try it.</p>
   <dl class="about-spec" data-ss-id="night-watch-about-spec"><div><dt>Type</dt><dd>…</dd></div><div><dt>Colour</dt><dd>…</dd></div><div><dt>Density</dt><dd>…</dd></div><div><dt>Modes</dt><dd>…</dd></div></dl>
   <ol class="about-frames" data-ss-id="night-watch-about-frames"><li data-frame="direction-night-watch">Name or state · Desktop 1280 × 800 · what it shows</li></ol>
   ```
6. **A view, if your prompt names one** (`night-watch-phone`): once your direction's parts are out, draw it the same way in `<folder>/draw/night-watch-phone/`, ids starting `night-watch-phone-`, every fact again, laid out for that width (SKILL.md section 2), never your desktop parts copied, and add its caption to your about part, `<li data-frame="direction-night-watch-phone">… · Phone 390 × 844 · …</li>`.
7. **Check once:** `node <skill>/assets/check.js -C <folder> night-watch` (and `… night-watch-phone` for a view), and fix what it lists, once, with Edit calls. Then stop: no other checks or rewrites.

Never push, save or touch another direction's files, and run no other command. If a Write is refused, stop at once and say only: refused.
